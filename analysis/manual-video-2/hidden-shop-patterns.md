原フレームの再抽出には、動画のフレーム番号を明示して選択できる。以下は証拠画像に使った15フレームを、元の30fpsのフレーム番号をファイル名にして抽出する完全なコマンド例である。出力先`patterns-source`は先に作成する。元動画はこのリポジトリには含まれない。

```bash
mkdir -p patterns-source
ffmpeg -hide_banner -i 'ScreenRecording_11-05-2026 12-41-49_1.mp4' -vf "select='eq(n,726)+eq(n,780)+eq(n,822)+eq(n,1194)+eq(n,1248)+eq(n,1308)+eq(n,2010)+eq(n,2130)+eq(n,2160)+eq(n,4314)+eq(n,4398)+eq(n,4428)+eq(n,4962)+eq(n,4980)+eq(n,5076)',showinfo" -fps_mode vfr -frame_pts 1 'patterns-source/%06d.png'
```

## 速さを優先した局所探索への使い方

1. 初期金壁ありは、その方向と可視床の接続から入口へ接近する。今回の6例とは別群として速度を測る。
2. 初期金壁なしでも、近い未観測域へつながる可視床や出口を候補として残す。形だけを店舗確定ラベルにしない。
3. 可視床から最短に試せる候補を1つだけ選び、短い区間を進んで観測を更新する。1回の予約を1〜2マス程度にすることは検証案であり、動画から確定した入力回数ではない。
4. 金壁・新しい床の接続・行き止まりのどれが新たに分かったかを確かめる。金壁が出たら探索から接近へ切り替える。金壁がまだ片側だけでも、候補を捨てない。
5. 地形に沿った折れ曲がりを許す。北へ伸びる通路から横入口が出るH05、金壁は見えても灰色壁を回るH06を直進マクロにしない。
6. 商品の必要領域が判別できた最初の地点で移動を止める。店の中央まで移動することや、金壁を画面中央へ運ぶことを完了条件にしない。

全マップ探索、複数枝の順回り、固定の長距離移動には広げない。探索全体に移動数と経過時間の上限を持たせる必要があるが、この録画には入力イベント列がないため、実用的な上限値はまだ確定できない。初期→金壁まで0.8〜3.0秒かかる5例と、途中ポーズのあるH03をもとに、実機で候補取得から可視化までの費用を測る。これらは人の画面変化の時間であり、自動化が達成した速度ではない。

上限までに新しい根拠が得られなかった場合は「局所探索では未判定」と記録する。対象候補が見えた場合には追加移動・リスタートを止めて保持する。未表示の商品を「対象なし」、未探索の領域を「店なし」にしない。

## 検証で残すべき失敗と不確実性

- 6例は後で近い店が現れた区間を選んだ資料であり、特徴の適中率・店の出現確率・見逃し率は算出できない。似た初期形状で人が見送った回も、店なしの正解にはできない。
- この動画からの手作業のパターン整理を、判定器が学習済み・実装済みと説明しない。同じ回の隣接フレームを未知評価に流用しない。
- 評価用には、別録画・別配置で、初期画像を先に固定してから判断を保存し、その後の探索結果と照合する。未来の画像から初期の出口位置や店舗方向を補わない。
- 初期金壁あり、初期金壁なし、近場探索をしなかった人の見送りを別群で測る。店の取りこぼしだけでなく、不要探索が見送り時間をどれだけ増やしたかも記録する。
- タッチ時刻・押下回数・拍との対応・最短歩数・自動入力の効果は未測定。速度の合否は取得、復号、判定、送信、入力反映を含む実機測定で決める。
- 対象商品の正例識別、長時間の耐久性、iPhone座標変換の正しさは、この資料では検証していない。
