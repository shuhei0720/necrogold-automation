# テストのルール

- 期待値は要件・人が確認した画像ラベルを出典にする。実装出力をそのまま正解にしない。
- 機能ごとにテスト1件でRedを実測してから最小実装。環境不足・コンパイル失敗を振る舞いのRedに数えない。
- assert削除、skip、常時成功モック、ケース削除で通さない。既に通るテストは理由を記録する。
- 単体、録画リプレイ、通信結合、実機E2Eを区別。実機E2Eは内部応答をモックしない。
- 同じランの隣接フレームを学習用と評価用に分割しない。配置/ラン単位で分離しチューニングに使った動画を未知評価と称さない。
- 人が見送ったランは未観測の店なし正解ではない。近くに店がある正例と探索結果を確認した負例を別に持つ。
- 全必須ケースと最新commitの結果を対応。未実施・古い結果・タイムアウトは成功ではない。
- テスト期待値を人がレビューできる一覧を残す。実機試験のないコミットは実用版にしない。

## 検証範囲の選択（2026-11-10 日本時間）

- 通常修正は変更箇所の単体と関連回帰を毎回実行する。受領した実画像/時刻/状態で停止箇所を確認し、再現範囲と欠落を明示する。
- 通信・並行処理・取得・入力境界を変えた場合は該当結合試験を追加する。単体だけでその境界の成立を主張しない。
- フルCI・全故障集合・大規模合成worldは毎回の実機前提にしない。節目、大きな変更、具体的な広い影響に応じて選び、その理由を記録する。既存試験を削除/skipして実行済みに見せない。
- 必須ケースは今回の変更の影響範囲から選び、対象commit/実行結果/未実施と理由を記録する。同一bytes等を根拠に再利用する過去結果は過去結果と明記する。
- native変更時のIPAビルドとsource/seal/実compiler/配布物同一性確認は維持する。client/資料のみの変更で新IPAを形式的に作らない。
- 品質と安全条件を時間の都合で緩めない。固定作業時間や20〜30分のノルマを置かず、必要な確認が終わるまで行う。
- 実機の商品到達率を主指標とし、毎拍歩行/速度も記録する。商品未観測、歩数増加、模擬試験やCIの成功を商品確認完了にしない。
