# テストのルール

- 期待値は要件・人が確認した画像ラベルを出典にする。実装出力をそのまま正解にしない。
- 機能ごとにテスト1件でRedを実測してから最小実装。環境不足・コンパイル失敗を振る舞いのRedに数えない。
- assert削除、skip、常時成功モック、ケース削除で通さない。既に通るテストは理由を記録する。
- 単体、録画リプレイ、通信結合、実機E2Eを区別。実機E2Eは内部応答をモックしない。
- 同じランの隣接フレームを学習用と評価用に分割しない。配置/ラン単位で分離しチューニングに使った動画を未知評価と称さない。
- 人が見送ったランは未観測の店なし正解ではない。近くに店がある正例と探索結果を確認した負例を別に持つ。
- 全必須ケースと最新commitの結果を対応。未実施・古い結果・タイムアウトは成功ではない。
- テスト期待値を人がレビューできる一覧を残す。実機試験のないコミットは実用版にしない。
