# アーキテクチャのルール

- 要件の正本は `docs/requirements/necrogold.md`、設計・順序の正本は `docs/plans/rebuild.md`。旧PDFは履歴。
- `legacy/r12/` は元ZIPと同一の保存資料。修正実装を継ぎ足さない。
- 取得、座標変換、認識、局所地図、判断、入力、通知を責務で分ける。採用言語と端末方式は実測してから決定。
- 画像には生成時刻・連番・向き・寸法・取得元を持たせる。回転、拡縮、入力座標変換を別にする。
- 画像キューは最新優先で上限を持ち入力は期限とキャンセルを持つ。曖昧な送信を自動再送しない。
- 初期画面の判定に未来の画像・商品位置・ラン番号を混ぜない。その時点で観測可能な地形のみ利用。
- 単一フレームの色の不在を全体の店なしにしない。未知・見送り・確認済み不在を別の状態にする。
- 端末トークンと私的設定はgitへ保存しない。ログに秘密値を出さない。
