# 要件定義: iPhone金壁リセマラ自動化

状態: ユーザーの必須7項目を再確認・反映済み。2026-11-05。実機合格の宣言ではない。実装方式は [プラン](../plans/rebuild.md) に分離する。

## 目的と対象

日本版ネクロダンサー、ケイデンス、通常オールゾーン1-1で、開始時に金壁が見える回を選び、金商人の商品を人の手操作より速く確認し、目的の「のろいのゆびわ」（本書の「呪いの指輪」と同じ対象）が見つかったらゲームをポーズして通知する。対象らしい候補も捨てずに保持する。動いても遅ければ要件未達である。ユーザーが自動化を使用する一連の操作は、同じiPhoneだけで完結する。PCや別端末の併用・常時稼働を必要としない。起動・停止・画像取得・判断・ゲーム操作・ポーズ・通知・結果確認を含む。

## ユーザーストーリー

開始を押すだけでポーズから直接復帰し、店を探し、商品を確認し、対象がなければ次のランへ移る。ユーザーの最新指示に従い、初版では開幕に金壁が見えない回を見送り、周回速度を優先する。金壁が見つかるまでリスタートを繰り返し、見つかったらビートに合わせて商品が見える位置まで歩く。商品を十分に確認して対象がなければ、金壁を探すリスタートのループへ戻る。対象があればゲームをポーズして通知し、以後の移動・リスタートを止める。利用者の停止や障害時の停止を除き、この循環を自動で続ける。

## 受け入れ条件

| ID | Given / When | Then |
| --- | --- | --- |
| PHONE-01 | 自動化の開始から停止・候補通知・結果確認まで | 同じiPhoneだけで完結。PC/別端末の操作や常時接続なしで、取得・判断・ゲーム操作を実機で確認 |
| START-01 | GAME PAUSEで開始 | 「ゲームを続行」を直接押し実際の1-1への復帰を確認。Options操作0回。実機20/20成功 |
| START-02 | 既に1-1 / OPTION / 別フロア | 1-1は判定へ。OPTION・別フロアに通常移動・リスタートを送らず状態を説明 |
| FRAME-01 | 黒・破損・古い・向き不明の画像 | 無効と判定し追加操作を出さない。通常ロード暗転は期限付き遷移として別扱い |
| FRAME-02 | 左側が下、画面端操作0 | 画像pxと入力ptを混同せず、実機の独立した正解位置へ操作が反映される |
| SHOP-01 | フェード終了後の有効な初期画像を判定 | 金壁が一部でも確認できれば接近。明瞭に見えない回は探索せず「開幕対象外」と記録してリスタート。描画不成立や判別不能はこの見送りと区別 |
| SHOP-02 | 金壁の部分表示、木・鉄扉、上下左右の入口 | ビートに同期して接近・開扉・移動を行い、必要な商品が見える位置へ到達。入力送信だけで到達成功としない |
| BEAT-01 | 移動・開扉などビートに依存する操作 | 現在のビート周期と位相に合わせ、入力が実機の受付時刻に届くよう制御。予定した拍で想定の移動/開扉が成立したことを実画面で確認。無同期の連打で代用しない |
| BEAT-02 | 起動・ポーズ復帰・リスタート・同期ずれ | ビートを取り直してから移動。古い位相や遅れた予約入力をそのまま使わない。取得/処理/入力遅延を含めて検証 |
| GOODS-01 | 店が見えるが商品が隠れる/画面端で切れる | 未観測の商品を「対象なし」と確定しない。読める位置を確保するか未判定として処理 |
| GOODS-02 | 本物の対象または対象らしい候補 | 入力予約を取り消しポーズ成立を確認して通知1回。自動購入・候補を捨てるリスタート0回 |
| RESET-01 | 開幕対象外 / 商品の対象なし確認 / 未判定スキップモード | リスタートして次ランを確認し、金壁の判定から自動ループを再開。旧画像で回数を増やさず曖昧な入力を無条件再送しない |
| STOP-01 | 利用者の停止、ロック、別アプリ/システム画面 | 待機中・予約中の入力もキャンセル。古いゲーム画像を理由に他画面へ入力しない |
| MODE-01 | 未判定を手元で確認 / 未判定回を飛ばす | 前者は保持。後者も対象候補は保持し商品不可視などの未判定による見送りは「対象なし」と別集計。開幕対象外は両モードで通常見送り |
| PERF-01 | 同等の配置・同じ操作設定で人と比較 | 見送り群・商品確認群の両方で人より速く、毎分の商品確認完了回数も人を上回る。認識誤りで処理数だけ増やす方法を認めない |
| RUN-01 | 長時間周回 | ハング・落ち・不明な入力再送がなく停止できる。タイムアウトをログで区別 |

## 性能の測定基準と提案値

数値は**提案中の合格値であり、達成済みではない**。動画1の人の基準は分析CSVを参照する。動画2は別資料であり単純に同じ分布へ混ぜない。

| 指標 | 計測区間 | 提案値 |
| --- | --- | --- |
| 見送り時間 | ランのHUD判読可能→次ランのHUD判読可能 | 中央値≤1.0秒、p95≤1.3秒 |
| 商品確認時間 | ランのHUD判読可能→必要な商品の判読可能 | 対応する配置で中央値≤3.0秒、p95≤4.0秒 |
| 人との比較 | 同じ採用方針・接近距離・扉・観測条件の各群 | 各群中央値を20%以上短縮。人の短い見送りを世界全体の店なし正解にはしない |
| 有効な処理量 | 実行開始→終了の全経過時間で商品判定完了数を割る | 同じ「開幕可視のみ」の方針で人の値を上回る。見送り数だけで評価しない |
| 再開 | ポーズ判読可能→1-1判読可能 | p95≤0.8秒、20/20成功 |
| 候補保持 | 候補判読可能→ポーズ成立 | p95≤0.5秒 |
| 鮮度 | 画像生成→判断時点 | p95≤150ms、有効観測10Hz以上を目安 |
| 停止 | 停止受付→新規入力禁止 / 停止成立確認 | ≤100ms / ≤300ms |
| 耐久 | 実機の同一版を継続 | 30分以上かつ500リスタート以上、ハング・落ち0回 |

取得・転送・復号・解析・ビート待機/再同期・入力・ゲーム側の反映を含める。ビート制約を守ったうえで、判断・経路・リスタート・入力遅延を短縮し、人より速い実効速度を満たす。送信頻度やリスタート回数だけを速度の合格根拠にしない。各群の件数、中央値、p95、失敗数、未判定数を併記する。新規の対応範囲内100回で判定完了率95%以上を暫定目標とし、候補の誤廃棄は1回でも不合格とする。

## 確定済みの前提と未確定事項

左側が下になる向き、画面端操作・設定0、木と鉄の扉、速度最優先はユーザー提供。対象アイテムの確実な正例、端末の取得経路と入力の能力、ビート周期/位相の取得・再同期方式は未確定。ビートに合わせた移動は必須であり、方式未定を要件からの除外とは扱わない。画面外の金壁探索は将来候補に分離する。動画の全探索結果を知らないため「開幕対象外」を世界全体の店なし判定とは扱わない。性能提案値はP1の実現性測定と人間の期待値レビューを経て正本に確定し、P6開始前に測定条件とともに固定する。結果を見てから合格値を緩めない。

開始前のタイトル・ロビー自動誘導は別の拡張として扱う。今回の必須起点は既存ランのポーズまたは1-1とし、既存不具合の開始不能解消を優先する。

## スコープ外

開幕に金壁が見えない回の探索、全マップの探索、ゲーム進行の完走、自動購入、別キャラクター・別モード・別フロアの周回、設定の無断変更、実測なしの速度・成功保証。


## 画像の比率と取得負荷（2026-11-05追記）

取得元から横長で正しい比率の画像を受け取る経路を優先し、縦長に変形された受信画像を毎回伸縮して戻すことを通常運用の前提にしない。向き・比率・認識精度と、取得から操作反映までの実測性能を併せて確認する。診断用画像の表示が整ったことを性能要件の達成とは扱わない。取得元の更新・別経路の採用は、実機版と利用可能なAPIを確認してから決める。


## ユーザー確認の7項目と対応（2026-11-05）

| 必須要件 | 受け入れ条件 |
| --- | --- |
| スマホだけで完結 | PHONE-01 |
| 人の操作より速い自動化 | PERF-01 |
| 金壁が見つかるまでリスタート | SHOP-01、RESET-01、RUN-01 |
| 金壁が見つかったら商品が見える位置まで歩く | SHOP-02、GOODS-01 |
| ビートに合わせて移動 | BEAT-01、BEAT-02 |
| のろいのゆびわがあったらゲームをポーズして通知 | GOODS-02 |
| なければ金壁探索のリスタートループへ戻る | GOODS-01、RESET-01 |

7項目は必須。商品が見切れている・認識できない状態を「のろいのゆびわなし」と確定しない。従来どおり初版は開始時に金壁が見える回（部分表示を含む）を採用し、画面外の金壁探索は追加しない。各項目の実機合格は未確認で、要件の記載と実装完了を区別する。


### 2026-11-06 歩行速度の明確化
最終的な歩行要件は、移動可能な通路では**毎ビートに1歩**進むこと。約0.52秒は提供動画の通常1-1の観測値であり、実行中のHUDから周期と起点を確認する。全体要件のスマホ単体・人間より速い操作は維持する。複数入力の予約だけでは受入とせず、実機動画の心臓と各歩の対応・歩行間隔を確認する。TEST-025の最大2連続入力は途中段階であり、曲がり角等の確認待ちを含む全経路での達成は未検証。

ステージ開始からの時間を基準にした予約入力を採用方針とする。開始と最初の拍のずれ・入力遅延は実測して区別する。ポーズ/再開の起点調整が必要で、リスタート命令の送信時刻をステージ開始時刻と仮定しない。TEST025時点ではライブHUD起点による2拍予約までを実装し、ステージ開始基準の校正は未完了。


### 2026-11-06 開扉・茶色い壁の操作
ユーザー確認: 商店の扉はその方向への入力で開け、茶色い壁はその方向への入力で壊せる。SHOP-02にこの操作を含める。開ける・壊す入力と、開いたセルへ進む入力を分け、開通だけでは歩数を増やさない。現在見える金壁の入口へ向かう経路上の茶壁を対象にし、金壁・石・未観測セルを同様に扱わない。実機での開通・進入と毎拍の連続移動を確認する。
