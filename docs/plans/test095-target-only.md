# TEST095: のろいのゆびわだけを判定する

2026-11-13（日本時間）。基準は2af68f6。[停止修正](test095-device-stops.md)に追加する判定契約の変更。全商品登録の案はユーザー指示により撤回した。CI/配布物照合済み。実機改善・速度・未知画像精度は未確認。

## 1. 概要

日本版ケイデンス通常1-1の金商店で、のろいのゆびわの主画像を商品帯全体から探す。対象外の商品名・種類の登録を次周回の前提にしない。対象または候補は保持し、十分に観測した商品帯で対象がない場合だけ既存の耐久intent付きリスタートへ進む。

## 2. 背景と範囲

094の対象外確定には有限商品bankとの一致が必要だった。未登録の商品があるたびに追加登録する設計は、対象だけを探す要件に合わない。旧mode0/1・旧bank1〜10・canonical15 sourceとELFは互換のため保存し、native周回だけ新mode2を使う。自動購入・宝箱開封はしない。

## 3. 判定の詳細

対象範囲は通常金商店の3価格位置に対応する商品配置。独立したSHOP・商人・唯一の価格行・3価格群・両端の観測条件を要求する。左の商品中心L、行基準Sに対し、有限の商品帯Bは[L-54,S+24,180,67]。通常の3商品位置と外側各1セルを含む。任意の世界全体・床に落ちた品・対応外の店配置の不存在を証明したとは扱わない。配置や外側の観測に疑いがあれば保持する。

B内に完全に収まる各主画像32×28/33×28/34×29の整数top-leftを漏れなく確認する。価格の中心だけを探さず、価格間・上下端・左右端も含む。Bの欠け、HUD重複、alpha異常、処理失敗、取消、期限切れは陰性にしない。広い探索ROIを塗り潰して「余剰物なし」の根拠にはしない。

canonicalのscore/厳密上界を使い、いずれかが.80以上なら候補として保持。同じprobeで主画像.88以上かつ完全観測の対象名IoU .82/coverage .90以上なら対象とする。別probeの最大値を合成して対象にしない。完全観測の強い対象名も陰性を拒否する。全商品の名前が読めることは主画像の全被覆の代用にも追加必須条件にもしない。

## 4. 試験方針

変更部のassertion Red→Greenを保存する。新しい主画像の全探索・certificate・Controller採用・Runtime選択/Wire出力の境界を選んで確認する。旧mode0/1と関連する対象判定・旧周回の拒否条件を回帰対象にする。実画像の再校正を繰り返さず、凍結後の完全/見切れ各1例の測定は校正用途と明示する。host時間をiPhone速度や未知精度と呼ばない。

## 5. 追加するケース

未登録の通常商品3つでも対象なしへ進めること、価格間の対象、各templateの境界配置、候補上界、強い対象名、max集約、価格/商人/端cap不足、見切れ/HUD/余剰物/alpha/取消/期限切れを確認する。certificateの改変・partial・未知policyをControllerが拒否することと、正常なpolicy2だけ既存intentへ進むことを確認する。

## 6. 実装手順

Ringのmode2と変更しないABI内のpolicy2証明→Controllerの独立検証→Runtimeのmode2選択とWireのgeneric結果→095の選択試験/実ビルドへ接続する。商品種別はgeneric対象外、商品IDは0。旧mode1のnamed/container識別を拡張しない。処理時間100ms・各鮮度期限・累積予算・owner/prefix/取消・UNKNOWN無再送は維持する。

## 7. commit前と配布

独立担当が有限Bの前提、各templateの全整数位置、候補veto、certificateから入力権限までの結合を確認する。最終同一sourceの選択host/Mac試験・seal・実compiler・IPA/完全sourceを照合し、固定GitHub Releaseへ保存する。実機では通常1-1ポーズから候補探索→商店→対象判定→陰性なら次周回を依頼する。過去の対策やCI成功を実機改善済みへ読み替えない。

## 8. 対象外と残る確認
