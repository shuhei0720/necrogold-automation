# P1.3: iSHでゲーム起動前にSIGSYSとなる問題

## 1. 概要
TEST-002はP1.2 / Python暗号でも、最初のdevice_info開始後にSIGSYSで終了した。iSH未実装のgetitimerを毎RPC前に呼んでいた互換性不具合を除去する。これはゲーム起動・取得を妨げる経路の修正であり、自動周回完成版ではない。

## 2. 背景・根拠
受領ZIPの1reportは取得0/12、画像0、capture_collection、終了-31、SIGSYS、crypto_engine=python。launch_appの開始記録なし。端末の具体的iSHビルドとsyscall traceは未取得のため、実機の唯一の故障原因までは断定しない。

iSH公式masterのkernel/calls.c（blob 23e3306b87508c4cc94a6e64987b31e18df20ac4）にはsys_setitimer（104）があるがgetitimer（105）がない。kernel/time.cはsetitimerのold_val返却を実装する。Python 3.9のsetitimerも以前の値を戻す。現行masterでは未実装呼出しはENOSYSだが、今回の実機はSIGSYSなので挙動の同一性は主張しない。出典とバージョンの限界を記録する。

## 3. 詳細設計
- RPCのgetitimer呼出しをゼロにする。setitimer(ITIMER_REAL, 0)の戻り値で既存タイマーを取り出す。既存タイマーがあれば値・周期を復元し、通信せずtimer_already_in_useで停止する。期限は専用子プロセスが所有し、他用途のタイマーを共用しない。
- SIGALRMハンドラーの設定後は、タイマー設定の失敗を含めてfinallyで旧ハンドラーを戻す。タイマー解除の例外でもハンドラー復元を試みる。復元不可を黙って無期限通信へ切り替えない。
- 独立レビュー第1周反映: 既存タイマーの復元残秒は単調時計の経過分を引く（期限済みなら最小正値で通知する）。周期は保持する。初回取得/設定はtimer_setup_failed、既存値復元はtimer_restore_failed、解除/handler復元はtimer_cleanup_failedとしてFATAL停止する。旧handlerが不明なら変更前にtimer_handler_unknownで拒否する。いずれも例外本文を記録せず、次のRPCへ進まない。
- RPC全体の絶対期限（暗号化〜HTTPヘッダー/本文〜復号）と親の全セッション期限/Ctrl+C回収を維持する。タイムアウトを単なるsocket無通信時間に弱めない。
- P1.2と同じ通信条件で比較できるよう暗号選択と取得条件は変更しない。旧R12を変更しない。許可RPCはdevice_info、1回だけのゲーム起動、screenshotのみ。
- 起動表示で「診断版」「操作サイトは起動しない」「続行のタップは行わない」を明確にする。launch_app開始・応答を表示し、応答だけでゲーム表示を確認済みにしない。
- 前のサイトが出ないのはP1診断版にHTTP UIがないため。今回新UI・タップ座標・自動周回を混ぜない。実画面取得成功後に最小実ゲームE2Eへ進める。

## 4. テスト影響範囲
protocol.deadline、CLIの説明とイベント表示、版番号。既存HTTP絶対期限、プロセス停止、入力禁止、暗号認証、原画像保持を回帰確認。TEST-002失敗を台帳へ保存する。

## 5. 新規テストケース
1. getitimer呼出しでSIGSYSにする子プロセスで、暗号化したdevice_info応答まで完了する（変更前は-31、変更後は0）。実iSHではなく互換性故障注入と明記する。
2. getitimerを利用不可にした状態でも実HTTPで端末情報→ゲーム起動→画像取得→端末情報を完了する。許可外メソッド・2度目の起動は送らない。保存画像を検証する。ローカル模擬E2Eであり実ゲームE2Eではない。
3. ヘッダー・本文のslow-dripと暗号処理の遅延でRPC絶対期限が効く。
4. 成功・例外・タイマー設定失敗で旧ハンドラーを戻す。既存タイマー/周期とネストを壊してRPCを続けない。
5. 初期表示がサイト/タップを実施しないことを明示し、起動応答を表示成功と混同しない。
6. 初回タイマー取得、既存値復元、設定、解除、handler復元の各失敗を分離し、開始前通信0件/後続通信0件を確認する。KeyboardInterrupt時の後始末と、暗号化+HTTP+復号の合計期限も検証する。

## 6. 実装順
独立プラン/網羅/安全レビュー → 上記テストのRed保存 → 小さな互換性修正 → Greenと全回帰 → 独立実装レビュー（最大3周） → 全ソース・根拠・配布ZIP保存 → TEST-003。既存P1.2のレビューとは別のBUG-P1-002として記録する。

## 7. コミット前テスト
全unittest、Python3.9構文、R12全40ファイルのハッシュ、ZIP全ソース一致、GitHubコミット照合。ホスト試験をiSH実機合格へ読み替えない。TEST-003ではゲームが前面になり原画像が得られるかを確認し、ポーズ解除E2Eの成功とは分ける。

## 8. スコープ外
新たなHTTP操作サイト、オプション操作、ゲーム内入力、自動探索/購入、性能達成・絶対成功の宣言。端末のシステムコールを追加実装したりOS設定を変えることもしない。
