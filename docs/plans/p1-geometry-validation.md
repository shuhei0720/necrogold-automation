# P1取得元修正: 横長の原画像を取得する

2026-11-05（日本時間）。ユーザーの性能要件により、受信後に縦横比を戻すプレビュー案は撤回。画像変換コードは未実装・未配布。実行版はP1.4のまま。

## 1. 概要

画像は取得元から正しい横長の比率で受け取る。受信後の幾何変換を通常の取得経路に追加しない。まず既存P1.4から1回の読み取りで実機の取得元版・build・対応能力を特定する補助スクリプトを完成させ、適用可能な修正経路を決める。

## 2. 背景

TEST-007のJPEG scale1は取得要求→検査の中央値409.465ms。これは周回全体の時間ではなく、人より速い要件の合格根拠には足りない。縦横414×896と横縦896×414は同画素数で、横長であること自体がデータ量を増やすわけではない。受信後の再拡縮には追加負荷と不可逆な画質低下があり、未測定のまま採用しない。

TEST-008の1792×828標準画像との比較でAPI画像の異方性拡縮が確認された。公開LoopCtrl commit `6fc759fcce397c92482c2a8c6f90244e5374aac9`（serverVersion=1.98.14）のActionHandlerはキャッシュpointSizeへリサイズする。初期app参照はSpringBoard。scale/format/quality/bundle_idだけでは出力の縦横を指定できず、resetやlaunch順序だけで直る保証もない。ScreenStreamはCGImageの寸法比率を基に縮小・動画符号化する別経路だが、iSHの動画復号コストと実機の向きは未確認。公開版と実機版の一致は不明。

既存P1.4のsafe_infoは版/buildを保存せず、video_stream/stream_ticketも既知能力リストにない。既存reportを再実行するだけでは未知事項が埋まらない。

## 3. 詳細設計

`tools/inspect_capture_source.py` はP1.4と同じフォルダをカレントにして実行できる、単体の補助コード。既存プロジェクトを再インストールせず、この1ファイルだけ追加して実行する。標準入力実行は提供しない。ファイル実行・子の--worker起動を実プロセスで確認する。

親が子Pythonを1個起動し、起動開始時の単調時計を基準に15秒の予算を管理する。プロセス生成のOS呼出し自体を時間内に中断する保証はなく、戻り次第残予算を適用する。終了回収待ちは別途最大1秒。子は既存load_pairing/Crypto/OwnedRpcTimer/Clientを使用し、allow_launch=Falseでdevice_infoを1回だけ（RPC期限8秒）。ゲーム起動、画像取得、rotate/reset/設定変更、位置情報reader、画像変換は行わない。native初期化が成立しない場合は既存fallbackを使い、利用engineを記録。

出力は標準出力の小さなJSONだけ。server_version/buildは最大64文字でASCII英数字と `. _ : + -` および空白のみ、protocol_versionは整数1〜10000、point寸法は有限数(0,4096]、pixel寸法は整数1〜8192、scaleは有限数(0,8]、boolは数値に含めない。欠落/不正は固定理由で示す。能力はrun_steps/wait_for/screenshot_stream/video_stream/stream_ticketの既知5種のみ。任意の名称やtoken/device_name/device_id、例外本文は出さない。上記値はサーバー申告でありcommit同一性/入力座標の証明ではない。

親はstderrを破棄し、JSONを再検査してから表示。子の出力が壊れた/異常終了/期限切れなら固定コードと数値終了コードだけを出す。SIGINT/TERM handlerは常にフラグを記録し、例外を投げない。子の登録後は最大0.1秒ごとの有期限待機で中断を検出し、killして回収する。連続signalが回収境界を中断しない。回収失敗はsource_info_cleanup_failedとして未確認を明示。補助コードが設置するINT/TERMのsignal handlerを終了時に復元する。既存タイマーのSIGALRM契約は変更しない。stdoutは選別済みJSONだけを生成する設計で、通信応答上限は既存Clientの上限を利用する。

取得元版が判明した後、当該版の「画像自身の寸法に基づいて出力し、入力point契約と混同しない」取得側修正を第一候補にする。既存の別取得経路は横長・比率・認識精度と取得/復号/判定/操作反映の実測比較を満たした場合に採用。未検証のバイナリ配布・自動更新はしない。
