# P1次期改修計画: 画像の幾何と入力座標の契約を分離する

状態: **計画。コード未実装、実機未合格**。2026-11-05（日本時間）。診断実行版はP1.4のまま。TEST-008の資料比較を根拠に、次の実装範囲と未解決点を整理する。

## 1. 概要

画像取得が成立した後の課題を、表示用/認識用の画像形状と、端末のタップ座標に分ける。まず取得元の版・寸法情報を安全に記録し、原画像を保持したオフラインの幾何検証を実装する。画像の見た目が直っただけで自動入力を解放しない。

## 2. 背景

TEST-007はnative_i386で12/12非黒取得、JPEG scale1の取得→検査中央値409.465ms。TEST-008標準画像は1792×828、API原画像は414×896または828×1792。同じ向きの文字配置が縦横別の倍率で対応した。P1.4が原バイト保存する以前に形状差が存在する。

公開LoopCtrlにはキャッシュしたpoint寸法へ描画する経路があるが、実機のserver_version/buildは未記録。現在の画像比較だけでは入力ptの向き・原点・寸法を確定できない。取得元を更新/差替えする判断もまだしない。

## 3. 詳細設計

### 取得元の診断情報

既存のdevice_info応答から、server_version、build、protocol_version、寸法/scaleの必要な値だけをallowlistで抽出し、欠落・型不正は未確認として残す。文字列の長さ・制御文字を制限する。device_id、device_name、秘密鍵、token、生RPC全体は追加しない。新しいRPCや設定変更は導入しない。server_version/buildだけではソースcommit同一性の証明にならないことも表示する。

### 画像の幾何検証

元画像と明示的に選んだ基準画像のハッシュ・寸法・EXIF・比較領域・変換候補を記録する。原画像は上書きせず、画像上の点の対応だけを求める。回転、縦横別の伸縮、切抜き/余白の有無を別候補とし、判断不能なら補正を採用しない。縦長という寸法条件だけで全画像へ補正をかけない。

TEST-008は1つのポーズ画面だけで、反対向き・プレイ画面・別アプリ・遷移画面の正解集合ではない。今回のROI/閾値をそのまま未知画像の合否基準にしない。基準画像の追加で処理が必要になっても旧資料を上書きせず出典を追加する。再拡大で失われた細部を復元したと扱わない。

### 入力契約の隔離

画像から画像への対応は、tapのptに変換しない。新しい診断でもinput_authorized=falseを維持し、既存のRPC allowlistを広げない。続行の単発E2Eは、別の計画で実機の独立した正解位置、前面/ロック、古い画面拒否、停止条件とともに検証する。実機の入力を検証する前にP2の周回へ進まない。

## 4. テスト影響範囲

改修対象はnecroprobeの情報抽出・結果出力とオフライン検証。旧R12の40ファイル、暗号実装、タイマー所有、既存の取得パラメーターは保持する。追加取得元情報が欠けても、従来の画像診断を根拠なく成功/失敗へ変えない。

## 5. 新規テストケース

- 取得元情報がある/ない/型不正/過長/制御文字あり。必要値以外の秘密値や端末名がreportへ混入しない。
- 独立した非対称図形を基準に、同方向の縦横伸縮、90/180/270度、余白/切抜き、EXIFの違いを区別する。今回の1画面に合わせた自己一致だけを合格にしない。
- 黒、欠損、無関係画像、複数候補が同程度、基準違いを判断不能とし、入力許可へ変えない。
- 原画像ハッシュの保持、画像同士の変換と入力ptを混同しない出力、原画像出力失敗時の扱い。
- RPC禁止条件、期限/中断・worker終了・秘密値非出力など既存の検証が維持されること。

幾何候補の数値閾値と未知画像の評価セットは実装前に固定する。現時点で未確定であり、値を後付けしてTEST-008だけに通る実装を作らない。
