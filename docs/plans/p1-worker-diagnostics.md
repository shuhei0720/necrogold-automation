# P1.2: TEST-001の子プロセス失敗を診断可能にする

## 1. 概要
TEST-001で2回ともworker_failed・取得0/12・未実施12となった。スクリーンショットで事実を記録し、原因を決めつけず、最後の処理段階と終了コードを残す修正を行う。

## 2. 背景
P1.1は子の標準エラーを破棄し、非0終了をworker_failedに丸める。秘密値を出さない意図でも、実機での異常終了を切り分ける情報が不足していた。54件のホスト通過はこの実機失敗を否定しない。手順・版の表示は正しい。

## 3. 詳細設計
- superviseのオプション辞書へ整数のreturncode、signal_number、既知signal_name、spawn_errnoだけを保存する。例外文やstderr本文・接続鍵は保存しない。
- workerがペアリング読込前・暗号初期化前・収集前にstageをcheckpoint保存する。ネイティブ異常終了でも直前stageを親が読めるようにする。
- Python例外は固定した型分類を残し、メッセージは残さない。最初のstop_reasonを上書きしない。親のプロセス結果と子のstageを最終reportへ併記する。
- Popen自体の失敗はworker_start_failedとし、保存失敗と混同しない。子が最初のreportを読めない場合は安全な固定文で知らせる。
- P1.2の標準暗号選択は変更しない。次回の比較は明示的な--python-cryptoで行い、同時に操作座標・通信条件・ゲーム設定を変えない。Python方式の速度を最終性能と評価しない。
- 実機原因は未確定。native初期化、子起動、report読込などは候補であり、終了コード・report未受領のまま原因にしない。
- 第1周レビュー反映: stageは「最後に保存した処理開始前の地点」であり、その処理の成功・故障原因ではない。checkpoint保存失敗では前のstageへ戻し、失敗した保存対象をcheckpoint_errorに分離する。
- 期限/Ctrl+Cと子の終了コードを分け、負の終了コードだけsignalとして解釈する。128+Nをsignalと推定しない。
- 親のreport読込失敗をreport_read_ok=falseとreport_read_errorに保存する。その場合の件数は初期予定であり、実際の未実行を証明しないと画面にも表示する。子の初読込失敗は固定文と予約終了コード74で扱う。
- 初期化のOSErrorを保存失敗と決めつけない。既知型の固定allowlistだけを分類に使う。元のstop_reason、親の停止理由、保存失敗を別々に残す。

## 4. テスト影響範囲
親子の監督・初期化診断だけ。取得・暗号プロトコル・入力禁止・R12は変更しない。停止結合fixtureは追加引数を転送する。今回の障害修正は新しいレビュー対象とし、既存P1.1の3周の後付け合格とは扱わない。

## 5. テスト
テストを先に追加し、正常子・任意の非0終了・シグナル終了・起動失敗を実プロセスで確認。暗号初期化のネイティブ異常終了を子で故障注入し、stage/終了コードと全試行未開始が両立することを確認する。秘密を含む例外のメッセージがreport/stdoutに出ないこと、元の原因保持、期限/Ctrl+Cの既存6結合ケースを回帰確認する。

第1周レビューの追加期待値: 初report読込失敗、3か所のcheckpoint失敗、未知の秘密入り例外型、暗号初期化のOSError、子非0終了と親report破損の同時発生を検証。漏洩検査はreport/stdout/stderrを含む。既存6停止ケースにも回収後のsignalとreturncodeの期待値を追加する。

## 6. 順序
手順・期待値の独立確認 → Red → 最小修正 → 全試験 → 実装とテスト/安全性の独立レビュー → 記録・コード保存 → ユーザー実機比較。最大3周。
