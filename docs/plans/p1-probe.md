# P1実装: 黒画像と遅延の切り分け

## 1. 概要
旧版とは別のPython 3.9対応ツールで、既存のLoopCtrlペアリングを読み取り、取得した画像を加工前のまま保存する。これは自動周回の完成版ではない。P1の端末計測を実施可能にする工程。

## 2. 背景
R12ログは起動後12枚の画像で画面を認識できず停止している。元画像が黒い場合、回転やリサイズでは復元できない。以前の前面確認・追加取得・解析の重複を一度外して、各層を計測する必要がある。

## 3. 詳細設計
- Python標準ライブラリと既存のPillowのみ。旧版Pythonフォールバックと同一のHMACプロトコル、任意で既存ネイティブ暗号処理を再利用。エンジン名を必ず記録する。
- 通信先は端末自身の127.0.0.1:8300に固定。既存token.jsonを読むだけで新規ペアリング・鍵変更をしない。候補キーが複数なら停止。秘密値や生のRPC本文をレポートへ含めない。
- 許可RPCはdevice_info、screenshotと、明示した起動オプション時の対象ゲームだけへのlaunch_app。tap、run_steps、設定変更、reset、通知は提供しない。
- JPEG scale 1、JPEG scale 2、PNG scale 1の3条件を比較。scaleの意味をこちらで推測せず、返されたメタデータと実ファイルの寸法を併記。回転・伸縮しない。
- 空/破損/黒画像・メタデータ不一致を別記。非黒画像もゲーム認識成功とは呼ばない。同じハッシュが続いても静止したポーズ画面があるため古い画像とは断定しない。
- JSON深さ16、ノード数10,000、HTTP本文12MiB、復号本文8MiB、画像4MiB/8百万画素/1辺4096を上限とする。NaN/Infinity・型不正・応答ID違い・MAC違いを拒否する。HTTPリダイレクトと曖昧な自動再送はしない。
- 親が絶対期限を固定し、子プロセスで通信・復号・画像解析・保存を実行する。親は期限/Ctrl+Cで子へTERM、0.3秒後も残ればKILLする。各RPCには残時間とRPC上限の小さい方を適用し、POSIXの総時間タイマーでも制限する。保存は毎回一意な一時名とatomic replaceを使う。保存できない場合は元の停止理由と保存失敗を両方表示する。通信障害は全条件を通して3連続で止める。形式など条件固有の失敗は条件別3連続でその条件を打ち切り、残る条件は試す。黒画像は取得済みの診断データとして残す。全体期限でも止める。Ctrl+Cは処理を中断し部分結果を保存する。iSHでのタイマー動作は実機確認が必要。
- 3条件を順に繰り返し、全試行を先に登録する。各時刻をホスト単調時計で記録。生成時刻/端末実行時刻は契約未確定のためnull、受信時刻を生成時刻と偽らない。画像保存の費用は通信/復号/画像分析と別計測。
- raw画像は条件別に非黒1枚・黒1枚、合計最大6枚だけ保存。全サンプルの小さいメタデータは残す。実行毎に専用ディレクトリを作り、以前の結果を上書きしない。
- 端末側入力期限/前面世代/取消は未検証と明記し、自動入力を解放しない。P2の実装はP1測定後に進める。

## 4. テスト影響範囲
新規ツールのみ。旧版40ファイルを変更しない。ホスト試験は通信契約・デコード・終了条件を検証し、端末での取得速度と新鮮さは証明しない。

## 5. 新規テスト
MAC/ID/JSON型・深さ・サイズ境界、鍵の選択曖昧性、禁止メソッド、画像形式・寸法・黒・非黒・縦画像保持、実在する黒画像/録画画像、失敗試行を含めた集計、同一画像の扱い、停止と期限、遅い分割HTTP応答、秘密値が結果に漏れないこと。期待値は仕様由来で固定。最初の実装前に振る舞いのRedを記録する。

## 6. 実装順
画像検査 → 認証通信/入力禁止 → 実行・集計 → iSH起動手順 → 独立レビュー（設計、テスト、セキュリティ）→ GitHubへ実装ブランチ保存。実機でしか決まらない性能・入力変換は未測定として引き継ぐ。

## 7. コミット前確認
`python3 -m unittest discover -s tests -v`、オフラインで添付の黒画像/録画画像を検査、POSIXローカルHTTP結合試験、Python 3.9構文互換検査、旧版SHA-256、秘密値と配布内容の確認。実行結果とRed/Greenを保存する。

## 8. スコープ外
タップ・自動リスタート・探索・購入・ペアリング再作成・背景動作の設定変更。今回のホスト側GreenをP1実機合格と呼ばない。

## 計測・集計の固定条件

標準は12試行（各条件4回）、最大600試行、全体45秒・1RPC8秒。ウォームアップ除外なし。条件別に予定/開始/完了/エラー/中断/未実施を出す。成功例だけの中央値・p95（nearest-rank）には件数を付け、失敗は0秒に置換しない。エンジンは実行全体で固定しreport.crypto_engineに記録する。

区間: 要求準備、HTTP往復、envelope解析/認証、復号、応答JSON、画像base64、画像整合検査/デコード、画像分析、raw保存、試行全体。capture_to_inspectedは保存を含まない。総経過は起動・中断・待機・保存を含み、capture完了数/秒を出すが、有効観測Hzとは呼ばない。生成時刻・画像の古さ・端末入力実行時刻は未計測。

P1に含まれる入力座標・端末側取消の実測は、このツールの後の小さな実機検証として残る。P1計測器のホスト試験とP1完了を分ける。
