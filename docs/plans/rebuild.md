# プラン: iPhone金壁リセマラの再設計

状態: プラン・テスト網羅レビュー済み。P1の取得診断ツールを実装し、ホスト54試験と3観点の独立レビューを終了。P1実機ゲートは未通過。要件の正本: [necrogold.md](../requirements/necrogold.md)。進め方: [ユーザー指定Codexフロー](../development-flow.md)。

## 1. 概要

動画の人の行動を、観測可能な画面状態・短い行動計画・画面での成否確認に分解する。最初に取得と入力の成立を検証し、その後に再開、リスタート、開幕に見える金壁への接近、商品判定を載せる。初版は金壁が見えない回の探索を省く。既存R12は比較資料として隔離する。

## 2. 背景

R12は黒画像で続行に進まない。以前の版にはOptionsへの誤入力、画像の縦伸び、前面判定での誤停止、数秒の取得・解析遅延があった。動画1では短時間の見送り中央値約1.37秒、商品観測約3.8秒。動画2には金壁未表示から店が現れる配置と、鉄扉から商品が見えるまでの系列がある。操作回数ではなく実際の動きと速さを検証する。

## 3. 詳細設計

### 配置と責務

| 配置案 | 責務 |
| --- | --- |
| `src/capture/` | 画像取得、時刻・連番・取得元、無効/古い画像の検出 |
| `src/geometry/` | 画素、正規化画面、端末入力ptの明示的変換 |
| `src/perception/` | 画面状態、プレイヤー、床/壁、木/鉄扉、商品の可視性 |
| `src/planning/` | 見えている金壁/入口への局所経路、接近の時間・歩数の予算 |
| `src/control/` | 状態遷移、ビート周期/位相への同期と再同期、入力1件の結果確認、キャンセル、停止 |
| `src/adapters/` | 実機通信・入力・通知。採用方式は計測後に決定 |
| `tests/` | 単体、録画再生、通信結合、実機ケース |
| `analysis/` | 出典、教師ラベル、観察根拠、再現コード |

これは論理配置案であり、PythonやSwift等の採用を先に固定しない。iPhoneだけで開始・取得・判断・入力・ポーズ・通知・停止・結果確認を完結できること、署名/導入/バックグラウンドの制約、実測遅延をP1で比較する。既存LoopCtrlの機能名だけを根拠に連続取得が使えると断定しない。

### 画像と入力の契約

各画像にcapture_time、receive_time、sequence、dimensions、orientation、sourceを持たせる。画像の正規化は回転と拡縮を区別し、2本目の横動画を再回転しない。frame age、現在の入力先、停止フラグを操作直前に検査する。キューは最新優先で古い画像を捨てる。

入力にはcommand_id、対象状態、期限、変換版、cancel generationを持たせる。未送信・送信済み結果不明・端末受付済み・反映確認済み・取消確認済みを分ける。通信の結果が曖昧なら新規入力を止めて読み戻し、同じ入力を無条件で再送しない。P1で端末側の実行期限・前面世代・送信済み入力取消の能力を検証する。ローカルキューの削除だけでは取消成立としない。端末側で保証できなければ未完了入力は1件に制限し、停止期限を満たす方式へ変更する。不明な入力の影響が解消したと確認できるまで運転を再開しない。画面変化がない場合は経路や前提を再評価する。

### 初版の採用方針

1. 新鮮で描画が成立した初期画像を確認する。ロード暗転・フェード途中・壊れた画像から金壁なしを決めない。
2. 金壁が一部でも確認できれば、現在見える地形から接近経路を作る。扉がまだ見えなくても金壁の断片を無視しない。
3. 有効な初期画像で金壁が確認できない回は探索せずリスタートする。これは「開幕対象外」であり「店なし」ではない。両モードで通常の見送りとする。
4. 金壁かどうか判別不能な画像は未判定として既存モードへ渡す。対象アイテム候補を見た場合は両モードで保持する。
5. 見えている金壁へは観測済み床の短い区間で接近する。方向転換、扉、壁接触、商品付近では再観測する。最初は最大2歩の区間を案とし、実際の有効入力間隔と取り消し能力をP1で測る。
6. 接近の総時間・歩数はP3で仮設定し、P4の上限付き実機試験で固定する。上限到達は「接近未完了」としてモードに従い、商品なしに読み替えない。固定前に本番運転へ進まない。

画面外の金壁の6例と特徴は将来用の研究資料として残し、初版の実装と合格条件へ混ぜない。今回の「パターン学習」は事例と条件の抽出であり、訓練済みモデルはない。ルール、経路、閾値、分類器のどの方式でも、調整に使うランと未知評価のランを分離する。未来のフレームやラン番号を現在の判断へ与えない。

### ビートに合わせた移動

移動と開扉はゲームのビート周期・位相へ同期させる。取得/判断/通信/端末入力の遅延を含め、対象の拍の受付時刻に届くよう制御する。固定間隔での連打を同期の代わりにしない。周期・位相の取得方式はP1で実現性を確認し、P4で実際の歩行と開扉の成立を検証する。起動・ポーズ復帰・リスタート後は再同期し、ずれた予約入力は流用しない。ビート制約下の移動待ちも人との速度比較へ含める。単体テストの時計一致を実機での移動成功に置き換えない。

### 扉・商品・終了

商品観測の結果は、商品ごとの判定と別に `coverage=complete/incomplete/unknown` を返す。completeは店内の判定対象範囲と商品配置を画像根拠で確認した場合に限定し、固定3商品を仮定しない。陰性リスタートはcompleteかつ全対象を判定済みかつ候補なしの場合のみ許可し、次ラン確認後は金壁判定のループへ自動復帰する。見えた2品が陰性でも別の品が画面外ならincompleteとする。

木と鉄は別ラベルで認識し、開扉と前進の画面変化を別に扱う。閉じた扉が消え商品が出ても、全商品が読めたとは限らない。商品の図柄・文字・値札・可視範囲を見て観測不足なら再観測点を求める。購入マスへ進まない。

候補を見たら予約入力の取消を先に行い、ポーズ成立を確認して1回通知する。前面がゲームであると確認できなければ無理にポーズ位置を押さず入力停止を優先し、保持未確認を表示する。通常暗転、取得障害、別アプリ、GAME OVERは別状態にする。すべての待機に期限と停止割り込みを設ける。

外部RPC応答は認証した相手と応答IDを照合する。受信前から本文バイト数を制限し、JSON深さ・配列数・base64の復号後量・画像総画素数を上限管理する。画像、設定は型・寸法・有限数値・座標範囲を検証してから使用する。管理UIを採用する場合はローカル接続範囲・認証・Host/Origin・本文上限・読込期限を契約化する。具体的な上限はP1の取得方式の契約に固定し、上限超過・巨大画像・不正JSON・NaN・無限値・範囲外座標を拒否する。拒否は入力0回、秘密値を含まない診断とする。

### 判断が残る点

| 論点 | 決め方と時点 |
| --- | --- |
| 取得/入力方式・端末版 | P1で能力と遅延を実測。不可なら方式を変更する設計記録を残す |
| 対象アイテムの正例 | P3〜P5前に名称と実画像を固定。近似の指輪だけで完成にしない |
| 接近の時間/歩数 | P3で仮予算。P4で木/鉄・方向別の到達時間を測り固定。画面外探索は初版対象外 |
| 性能の提案値 | P1で実現性を記録し、期待値の人間レビューで採用値を要件正本へ反映。P6開始前に条件と版を固定。未確定は合格にしない |
| 人との同条件比較 | 同じseed/配置を再現可能か確認。不可なら地形・距離・扉・遮蔽で層別し比較限界を記録 |

## 4. テスト影響範囲

座標変換は再開、方向入力、ポーズ、リスタートすべてに影響する。取得方式は鮮度・前面・キャンセル・バックグラウンドに影響する。採用方針と接近変更は部分金壁の見落としと商品確認回数/分を同時に評価する。学習データ変更は全認識セットで再評価し、未知評価への漏洩を点検する。旧版の51件の模擬テストだけではこれらを確認できない。

## 5. 新規テストケース

| ケース | 対応要件 | 期待結果と確認方法 |
| --- | --- | --- |
| T00 iPhone単体の一連動作 | PHONE-01 | PC/別端末を使わず開始→金壁見送り→商店接近→商品判定→ポーズ/通知またはリスタート→停止/結果確認を実機で行う |
| T01 ポーズ/1-1/OPTION/別フロア | START-01/02 | 直接続行のみ。誤Options0回。実機20回と録画回帰 |
| T02 黒/破損/古い/向き不明 | FRAME-01/02 | 入力0。年齢の閾値直前/一致/直後、連番戻り、画像寸法変更 |
| T03 通常暗転/停止した取得 | FRAME-01, RESET-01 | 状態に応じた期限。期限前/一致/後。無期限待ちなし |

| T05 金壁が見える/部分だけ/見えない/描画途中 | SHOP-01 | 有効画像の非可視例は開幕対象外として見送り。部分金壁は採用。描画不成立は遷移待ち。後で店が見えた事実を初期入力へ漏らさない |
| T06 見える金壁への接近未完了 | SHOP-02, MODE-01 | 接近上限の直前/一致/直後。対象なしへ読み替えない。上限でモードに従う |
| T07 木/鉄、上/下/横、HUD重なり | SHOP-02 | 開扉と移動を区別。扉未反応で古い計画の連打なし |

| T09 候補発見と入力予約の競合 | GOODS-02, STOP-01 | 取消後の移動・リセット0、重複通知0。購入0 |
| T10 通信切断/タイムアウト/前面変更/ロック | STOP-01, RESET-01 | 送信前後・端末実行直前で故障を注入。予約/送信済み取消の成否、期限切れ後の遅延実行、前面世代変更を確認。結果不明入力を再送しない |
| T11 2モードと新ラン識別 | MODE-01, RESET-01 | 接近上限/商品不可視/金壁判別不能/商品認識不能で動作を分岐。候補はどちらも保持。開幕対象外は通常見送り。旧画像を新ランとして数えない |
| T13 外部入力の制限 | FRAME-01/02, STOP-01 | 型不正、空、巨大、不正形式、NaN/無限値、上限の直前/一致/直後を拒否/許可し操作0を確認 |
| T14 未来情報遮断と停止割り込み | SHOP-01, STOP-01 | 同じ観測prefixで後半だけ異なるfixtureの初期判断が同じ。待機・復号・再観測・通知中の停止も取消 |
| T15 ビート同期と再同期 | BEAT-01/02、SHOP-02 | 予定した拍で移動/開扉が成立することを実機で確認。起動/復帰/リスタート/遅延時に同期を取り直し、ずれた入力の連打・重複歩行を防ぐ |
| T12 速度・品質・連続実行 | PERF-01, RUN-01 | 見送り100例、店舗30例以上を実機測定。中央値/p95/失敗/未判定。30分かつ500リスタート |

テスト期待値はこの表で人のレビューを受けられる状態にする。学習/評価分離、各ケースのfixtureと正解根拠、実機結果はケース台帳に記録する。今回の資料作成だけでT00〜T15を通過したことにはしない。

性能計測はホストと端末の単調時計を対応づけ、時刻同期の誤差も記録する。取得要求開始→capture生成→受信→復号開始/完了→検出開始/完了→判断→入力送信→端末実行→画面反映を別イベントとする。APIが生成時刻や内部処理を公開しない場合は推定値と誤差/未分離を記録し、分離計測済みとは呼ばない。鮮度の閾値超過と停止受付→新規禁止/成立を別集計する。T12の全試行を先に登録し、失敗や未判定を無言で除外しない。完了率の分母は対象範囲の全試行で、タイムアウト・認識不能も未完了として数える。候補誤廃棄は1件でも不合格。時間未確定例は打切り/失敗として残し、成功例だけの時間を全体の性能と呼ばない。成功例の中央値/p95には失敗/未完了の分母と率を必ず併記。毎分の商品確認完了回数は準備後の開始から停止までの全経過を分母とし、失敗・再試行・待機も含める。候補保持で通常周回を終えた点と外部中断は理由付きで区別する。要件正本の指標を1行ずつ判定し、未測定を合格にしない。

## 6. 実装順と担当

全担当は利用環境のモデル設定を継承し、モデル名を推測して固定しない。

| 工程 | 担当 | 完了条件 |
| --- | --- | --- |
| P0 要件と資料 | 主担当＋動画分析担当 | 出典・初期観測・結果を分離。要件/プランを独立レビュー |
| P1 取得・入力の計測器 | 主担当。独立担当は結果検査 | 有効画面・新鮮さ・座標・停止を実機で連続10分確認。ビート周期/位相の取得・入力遅延を測り、方式と予算を決定 |
| P2 開始・リスタート | 主担当 | T01〜T04/T10/T11の該当部分。直接続行20/20、正常暗転復帰、取消 |
| P3 認識と接近候補 | 主担当＋データ整理担当 | T05〜T08の録画認識/可視性/候補生成部分。未知評価を分離し仮の接近予算を記録。実機到達をこの段階の合格にしない |
| P4 局所移動 | 主担当 | T05〜T08/T15の実機部分。ビートに同期し、木/鉄/上下左右の開扉と歩行を確認して商品まで到達。実測から接近予算を固定 |
| P5 候補保持と通知 | 主担当 | 対象正例、候補取消競合、通知1回、購入0 |
| P6 速度・耐久 | 主担当＋独立集計担当 | T12と全必須ケースを同じ版で確認 |
| 各節のレビュー | design/edge-case/security担当 | 作成経緯を渡さない独立レビュー。最大3周 |

各機能はRed→Green→Refactor。P1が成立しなければ探索アプリの実装へ進めない。P2が通る前に探索機能を積み増さない。資料・保存作業はこの実機ゲートと区別して継続できる。

## 7. コミット前テスト実行

現在の保存コミットでは、R12全40ファイルのSHA-256照合、分析JSONの構文、参照先、抽出画像寸法・出典、保存対象一覧、既知の秘密値形式と私的設定の走査、証拠画像の目視を確認する。実行生成物は無視される専用領域へ隔離し、確認した資料だけを証拠に採用する。これは保存の整合確認でありゲームの合格試験ではない。

実装方式確定後、単体・録画再生・結合・実機を別コマンドとして用意し、確定したコマンドを本節とCIへ記載する。未作成コマンドを実行済みとして掲載しない。PRでは最新commitの必須CIと実機ケースの証跡を要求する。実機未実施をモックで成功に置き換えない。

## 8. スコープ外

R12のその場しのぎの改版配布、開幕に金壁がない回の探索、全マップ探索、別モードの自動攻略、自動購入、未検証のネイティブ導入を前提とした完成保証。ユーザーの継続指示によりP1計測器の実装へ進む。具体化は[p1-probe.md](p1-probe.md)。P1実機ゲートを通過するまでゲーム操作ループは追加しない。
