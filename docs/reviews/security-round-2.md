# セキュリティ・運用レビュー 第2周

レビュー日: 2026-11-05（日本時間）

第1周のSEC-01〜SEC-03に対する計画・除外設定の変更だけを再確認した。初版を「開幕に金壁が見える回」に限定する最新方針を前提とし、画面外の金壁探索を初版の必須要件として扱わない。編集したのは本レビュー文書のみ。

## 判定

第1周の3件は、**再実装計画への反映漏れとして解消**。この確認範囲の残件はP0: 0件、P1: 0件、P2: 0件。新しいゲーム操作コードの実装完了や、端末上での安全・停止性能の合格を意味しない。

| 指摘 | 結果 | 確認した変更と位置 |
| --- | --- | --- |
| SEC-01 / 元P1 | 計画上解消 | `docs/plans/rebuild.md:34` に未送信・結果不明・端末受付済み・反映確認済み・取消確認済みを区別する契約を追加。P1で端末側の実行期限・前面世代・送信済み取消能力を確認し、ローカルキュー削除だけで取消成立としない。不明入力の影響解消まで再開禁止、保証できない方式は変更する。T10（同`:84`）で実行直前の故障・期限切れ後の遅延実行・前面世代変更を検証し、同`:92`で停止受付、新規禁止、停止成立を別集計する。 |
| SEC-02 / 元P1 | 計画上解消 | `docs/plans/rebuild.md:55` に認証相手/応答ID照合、本文バイト数、JSON構造、配列、base64展開量、画素数、型・有限性・座標範囲の制限を追加。管理UIを採用する場合の接続範囲・認証・Host/Origin・読込期限も対象とし、上限をP1の契約で固定する。T13（同`:86`）に不正型、巨大入力、NaN/無限値、上限境界の拒否と入力0、T14（同`:87`）に復号などの処理中の停止を追加。 |

未完了入力1件への制限それ自体を取消成立の証明にはしない。これは、プランに併記された「停止期限を満たす方式へ変更」と「影響解消まで再開しない」を含めてSEC-01の解消と判断した。将来のP1では端末側の遅延実行が残らないことを実測する必要がある。

## 範囲変更との整合

`docs/requirements/necrogold.md:21` と `docs/plans/rebuild.md:38` 以降は、新鮮で描画の成立した初期画像から開幕採否を決め、部分金壁は採用、金壁非可視は「開幕対象外」、描画不成立や判別不能は別扱いとしている。候補保持・自動購入禁止・別画面への入力禁止（要件`:24`、`:26`）は維持され、範囲縮小によってSEC-01〜03の防御を省略する記述は確認されなかった。

## 検証の限界

静的な差分再確認のみ。第1周の全面秘密値走査、画像目視、旧版40ファイル照合は繰り返していない。今回追加された保存前の検査は、最終コミット対象が確定した時点で主担当が実行する。新コード・通信試験・iPhone実機試験は未実施であり、R12が動作保証版になったわけではない。

具体的な入力上限と端末方式はP1で固定し、実装時はT10/T13/T14を含む対応試験と人間レビューで確認する。これらの未実施事項を、現在の資料レビューの合格と混同しない。
