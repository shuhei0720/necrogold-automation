## 指摘

### TR-01 / P1: ルール調整でも必要な未知評価の分離が、分類器採用時に限定されている

- 箇所: `docs/plans/rebuild.md:44`、`docs/plans/rebuild.md:74`、`docs/plans/rebuild.md:94`。
- 基準: `docs/rules/testing.md:7`、`docs/requirements/necrogold.md:21`。
- 問題: 設計本文は「分類器が必要な場合のみ学習用と未知評価用をラン単位で分ける」としている。探索優先度や上限の調整でも評価対象への適合は起きるため、分類器の有無は分離要否の条件にならない。T05の具体例は既知の動画2だけで、初期金壁なしの未使用ランを合格条件に含めることも明記されていない。P3の「未知評価を分離」と本文の条件付き分離が食い違う。
- 壊れる例: 動画2を見ながら左上通路の優先度と探索歩数を調整し、同じランまたは隣接フレームを「未知評価」とする。T05は通るが、金壁が初期画面にない別ランの近隣店を探索上限で毎回見送る。
- 修正案: 分類器、手書きルール、閾値、探索予算のいずれの調整でもラン/配置単位の分離を必須にする。P3の台帳に、初期金壁なしの未使用正例、左右や地形が異なる正例、局所探索を確認した負例を対応づける。探索範囲外と未探索は負例にせず未判定とする。既知動画での回帰合格と未使用ランでの評価を別結果として残す。

### TR-02 / P1: 性能試験の時刻・母集団・合否判定が不足し、同じ出力でも合格判断が変わる

- 箇所: `docs/plans/rebuild.md:32`、`docs/plans/rebuild.md:81`、`docs/plans/rebuild.md:92`。
- 基準: `AGENTS.md` の「Human-faster operation」項、`docs/requirements/necrogold.md:35`〜`46`。
- 問題: T12は見送り100例・店舗30例と集計値を挙げるが、要件にある取得・復号・検出・入力送信・画面反映の個別計測、画像生成と判断の時計の対応、候補保持・鮮度・停止の合否への対応が具体化されていない。また、失敗・未判定を併記する規則だけでは、速く成功した試行だけを所要時間の母集団に残すことを防げない。判定完了率95%以上の分母や候補誤廃棄1件で不合格とする検証もT12の期待結果に接続されていない。
- 壊れる例: 100回中95回が0.7秒で終了し、5回が10秒でタイムアウトする。成功95回だけで中央値・p95を出す一方、失敗数は別欄へ書き、人より速いと判断する。別の例では、送信応答時刻を入力の画面反映時刻として扱い、端末側の待ちを速度から落とす。いずれも現在のT12の記載だけでは除外できない。
- 修正案: P1で計測イベントと時計の対応方法を固定し、取得開始/画像生成/受信/復号完了/検出完了/送信/画面反映を識別する。画面間の比較は同一の時刻基準から測る。T12または対応ケースに要件表の各指標、閾値、試行数、実機証跡を直接対応づける。対象試行・層別条件・タイムアウト値を測定前に固定し、失敗・未判定を除いた条件付き時間を全試行の性能と呼ばない。時間が確定しない試行の扱いを事前に決め、判定完了率の分母と候補誤廃棄の即時不合格を明記する。提案値の確定・変更は既存計画どおりP1で扱い、レビュー側で数値を追加しない。

### TR-03 / P1: 未判定2モードの試験が探索上限に偏り、商品が読めない場合の保持を保証しない

- 箇所: `docs/plans/rebuild.md:77`、`docs/plans/rebuild.md:80`。
- 基準: `docs/requirements/necrogold.md:23`、`docs/requirements/necrogold.md:25`〜`27`。
- 問題: T08は不可視の商品を陰性にしないこと、T11は探索上限時の2モードの分岐を確認する。商品遮蔽が解消できず「未判定」となった後、利用者が選んだ保持モードを実際の制御が守ることを検証するケースがない。観測不足の分類テストと探索上限だけのモードテストを別々に通しても、商品未判定からの制御は漏れる。
- 壊れる例: 商品が画面端で切れ、認識器は正しく未判定を返す。しかし制御が商品の未判定を常にスキップとして扱い、保持モードでもリスタートする。T08は陰性を返していないため通り、T11の探索上限分岐も通る。
- 修正案: T11の入力を「探索上限」と「商品が十分に観測できない」の両方に拡張し、各2モードを確認する。保持モードではリスタート0回、スキップモードでも対象候補があれば保持する。対象なしを確認した場合、未判定の場合、候補がある場合を別の期待値にする。取得障害や前面不明は通常のスキップに落とさず、既存の入力停止規則と接続する。

### TR-04 / P2: 未来情報を使わない方針はあるが、違反を検出する試験がない

- 箇所: `docs/plans/rebuild.md:44`、`docs/plans/rebuild.md:74`、`docs/plans/rebuild.md:83`。
- 基準: `docs/rules/testing.md:3`、`docs/rules/testing.md:7`〜`8`。
- 問題: 動画後半の情報を正解ラベルに限定する方針は適切だが、T05は「観測だけで探索候補を作る」という期待にとどまる。リプレイ入力に後半フレーム、最終結果、店方向を含むファイル名やラベルが混ざったとき、検出する手順が未定である。
- 壊れる例: リプレイfixtureが全フレームと最終店位置を1つのオブジェクトとして判断器へ渡し、初期画面で見えていない店位置を探索優先度へ使う。実機では取得できない情報でT05だけが成功する。
- 修正案: 判断器に渡すfixtureの項目を現在までの観測・入力履歴に限定し、正解ラベルは評価側だけが保持する。観測済みprefixが同じで後半だけが異なる2系列を用意し、分岐前の判断と入力が同じになる試験を追加する。乱数を使う方式なら同じ乱数条件で比べる。新しい観測が到着した後の判断変更は許容し、将来の情報を先取りした場合だけ失敗させる。

### TR-05 / P2: 利用者の停止経路が、候補検出や通信障害による取消に埋もれている

- 箇所: `docs/plans/rebuild.md:73`、`docs/plans/rebuild.md:78`〜`79`。
- 基準: `docs/requirements/necrogold.md:26`、`docs/requirements/necrogold.md:43`。
- 問題: T04には停止の実機確認、T09には候補と予約入力の競合、T10には通信障害・前面変更・ロックがある。一方、利用者が停止を押す経路について、取得待ち・再試行待ち・予約入力との競合を起こす試験は明示されていない。内部の取消処理だけ正しくても、利用者の停止イベントを受け付けない待機が残り得る。
- 壊れる例: 候補検出と前面変更の取消は通るが、取得のタイムアウト待ち中は停止ボタンのイベントを処理せず、停止後に予約済みの方向入力が送られる。
- 修正案: T10に利用者の停止を独立した起点として追加し、取得待ち・バックオフ待ち・送信直前・送信後の各点で試す。停止受付、以降の新規送信禁止、観測による停止成立を別イベントとして記録する。送信済み入力と新規送信を区別したうえで、要件の100ms/300msに対応づける。前面変更・ロック時の停止試験も独立して残す。

## 正常・異常・境界の点検

- 画像年齢の閾値直前/一致/直後、連番戻り、寸法変更、暗転期限の前/一致/後、探索上限の両側は計画済み。実装方式と探索上限を確定する際、境界一致時の期待値も台帳に固定する。
- 木/鉄扉と上下左右の入口は必須範囲に含まれている。台帳では木/鉄と向きの組合せを行に分け、単に木を上・鉄を横で1例ずつ試しただけで全組合せを検証済みにしない。
- 初期金壁なしの正例と、局所範囲の探索で確認した負例を分ける方針は適切。人が見送っただけのランや範囲外は「店なし」の正解にしない。全マップ探索は要求しない。
- 商品切れ、HUD/文字の重なり、類似指輪、候補と予約入力の競合は計画済み。候補検出前後で許可される入力を分ける。認識方式を決めた後に閾値を使う場合は、その境界両側を追加する。
- 通信結果が不明な入力の無条件再送禁止、通常暗転と恒久的な取得障害の区別、各待機への期限と割り込みは設計にある。TR-05はその利用者停止経路を試験で閉じるための指摘である。

## モック・録画・実機の分離

`docs/rules/testing.md:6`、`docs/plans/rebuild.md:104`〜`106` は、単体・録画・通信結合・実機を分け、旧版51件や保存整合性チェックを実機合格と扱わない。これは適切である。現時点の結果はすべて「新規実装・実機試験未実施」のままにする。

台帳は各ケースに必要な試験層、入力資料、期待値の出典、対象版、実測結果、証跡を持つ。録画リプレイは認識と判断の再現には使えるが、端末での続行・向き・入力反映・前面変更・速度の実証には置き換えない。今回の指摘対応でゲーム操作コードや実機結果を作成する必要はない。
