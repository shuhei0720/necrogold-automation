## 残存指摘

### TR2-01 / P2: 復号と検出を別々に測るイベントが性能計測列にない

- 箇所: `docs/plans/rebuild.md:92`。
- 基準: `AGENTS.md` の「Measure capture, decoding, detection, command submission and visible input effect separately and end to end.」。
- 問題: 現在のイベント列は画像生成→受信→判断→入力送信→端末実行→画面反映であり、受信から判断までに含まれる復号時間と検出時間を分離できない。総時間の合否、失敗の集計、時計の対応は修正済みなのでP1とはしない。
- 壊れる例: 受信後に復号400ms・検出10msがかかっても、受信→判断410msという記録だけでは、以前の取得・解析遅延のうち何が支配的かを確認できない。取得開始時刻がなければ、画像生成前の取得待ち時間も工程別に測れない。
- 修正案: P1で固定するイベント列に取得開始、復号開始/完了、検出開始/完了を明示する。APIの都合で内部区間を分離できない場合は、その区間を未分離と記録し、個別計測済みとは扱わない。新たな速度目標や実装方式の追加は不要。
