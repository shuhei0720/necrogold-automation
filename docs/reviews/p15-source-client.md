# P1.5 取得元geometryを要求する診断クライアント

2026-11-05（日本時間）。[NG-G1計画](../plans/p1-source-geometry.md)で予定した「取得元ビルド成功後」のクライアント段階。API版1.98.14-ngg1のIPAは実ビルド・検査成功。新クライアントは端末未実施。

## 実装

`--source-geometry`を親→worker→collectへ渡す。最初のdevice_infoの新capabilityを必須にし、失敗・欠落時はlaunch/screenshot前に停止。元の3形式条件にgeometry指定を追加し、旧版での無視、形式・実寸・出力EXIF・取得元メタデータの不一致を失敗として残す。

原画像のデコードは従来の1回。既存の整合性verifyと画素検査は保持し、新モード用にもう一度デコードしない。回転、縦横リサイズ、再符号化を追加しない。入力側point寸法は画像側image_point寸法と区別し、入力未承認/P1未合格の状態を維持する。指定なしの既定取得経路を保持。R12は変更しない。

## TDDと結果

- 実装前はcapability不成立でもゲーム起動/取得へ進み、旧応答を受理する失敗を観測。
- 追加の出力EXIF制約は2/6/8を受理するRed→拒否Green。
- sourceから40.5になる値を申告側40.499999999に変えた場合、誤った幅40を受理するRed→拒否Green。期待幅は申告値ではなくsource再計算から求める。
- 画像検査を故意に二重実行した変異で、実decode入口の呼出回数が3→6となる失敗を観測。変異除去後Green。
- **全131ホスト試験成功、25.025秒**。[全ログ](../validation/p15-client-full-final.txt)。追加16試験と既存115試験。複数の不正metadata・向き・境界をsubTestで確認。
- ホスト試験は模擬画像/応答を含む。iSHでの実行、UIKitからの画像、速度は未確認。
