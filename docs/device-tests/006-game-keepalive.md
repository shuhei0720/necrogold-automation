# TEST-006: 同じP1.4に一時的な継続処理を付けてゲーム画面を取得

状態: **手順準備・実機未実行**。2026-11-05（日本時間）。診断コードはP1.4のまま。新しい実行版への入れ替えは不要。

## 1. 概要

TEST-004（ゲーム起動あり、0/12取得）とTEST-005（iSH前面、11/12取得）を受け、旧版にあった`/dev/location`の読み捨てを試験の間だけ動かす。ゲーム表示中に画像取得が進むか比較する。

## 2. 背景

TEST-005の保存原画像3枚には今回のiSHコマンドと進む試行表示が写っていた。11試行は非黒で完了、12番目は中断、全体45115.262ms。通信・復号・画像展開・保存がこの前面条件では成立した。P1全体は未合格。

iSHの[公式Wiki](https://github.com/ish-app/ish/wiki/Running-in-background)と[開発メンバーの説明](https://github.com/ish-app/ish/issues/1516)では、`/dev/location`の読取りは位置情報取得を開始し、バックグラウンド実行を可能にする方法として説明されている（2026-11-05確認）。端末上での今回の有効性は未確認。位置情報そのものは`/dev/null`へ捨て、保存・送信しない。

旧`legacy/r12/start.sh`にも同じ読取り処理がある。P1.4の診断コードへ自動で組み込む判断は、この試験結果を受けて別の修正プランで行う。

## 3. 比較設計

TEST-004の手順指定と同じP1.4・Python暗号・12試行・45秒・ゲーム起動ありに戻し、試験中の位置情報読取りを追加する。TEST-004の実際の起動引数は未記録のため、完全に同一条件だったとは保証しない。今回は開始・終了時の補助プロセス生存表示も終了画面に残す。

`kill -0`は読取りプロセスの生存確認であり、位置情報の配信やiOSによるバックグラウンド許可を保証しない。読取り許可の確認画面や、ゲームへの切替後にiSHへ戻った時刻が結果に影響するため、観測した事実を添える。取得対象画面が異なり、CPU負荷や画像バイト数も変わり得るため、TEST-005との速度比較で性能改善を断定しない。

## 4. 影響範囲

既存プログラム、ペアリング、設定ファイル、旧R12は変更しない。位置情報の読取りは今回起動したプロセスだけに終了時の停止要求を送る。SIGTERM送信だけでは端末上の停止完了を保証しない。`killall cat`や常駐登録は行わない。位置情報の許可が新たに表示された場合は、その用途を確認して許可するかをユーザーが選ぶ。許可しない場合はiSHでCtrl+Cを押して終了し、条件未成立として記録する。

## 5. 判定条件

| 結果 | 判断 |
| --- | --- |
| ゲームのポーズ画面を1枚以上保存 | この条件でゲームの取得が成立した範囲だけ確認。12枚完了・高速化・鮮度・P1全体は別判定 |
| ゲーム表示のまま取得が進み、約45秒で終了 | バックグラウンド継続処理の有効性を支持。単一試験だけで全問題の原因解消とはしない |
| 黒画像を返す | 通信は動いていてもゲームの有効画像取得は未合格。取得元を次に調べる |
| iSH画面だけを返す | ゲーム画像の取得成功にはしない。起動時期、取得元、画面の取り違えを確認 |
| 取得0枚または期限が大きく延びる | 継続処理の有効性、取得API、処理段階を調査。パラメーターを無断で増やして再実行しない |
| /dev/locationが読めない、補助プロセス開始失敗、許可しない | 試験条件未成立。ゲーム取得失敗や位置情報処理の有効性の否定にしない |
| 終了時に補助プロセスが既に終了 | 途中終了時刻は未計測。継続条件の成立を推測しない |
| 一部取得後に時間切れ | 成功画像と中断/未実施を別記録。45秒で12試行完了できるとは保証しない |

## 6. 実行手順

LoopCtrlは以前の接続状態にする。ゲームは通常オールゾーン1-1のポーズ画面、端末は左側が下。iSHへ戻り、既存の`/mnt/necro_p14`で次のブロック全体を1回だけ実行する。`P1.4`であることはTEST-005で確認済み。今回はゲームが自動で開く想定で、「ゲームを続行」は押さない。

```sh
cd /mnt/necro_p14 && (
  set -eu
  if [ ! -r /dev/location ]; then
    echo 'TEST-006: /dev/locationを読めません。試験は開始していません。'
    exit 1
  fi
  cat /dev/location >/dev/null 2>/dev/null &
  keeper=$!
  trap 'kill "$keeper" 2>/dev/null || true' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  sleep 1
  if ! kill -0 "$keeper" 2>/dev/null; then
    echo 'TEST-006: 継続用プロセスを開始できませんでした。'
    exit 1
  fi
  echo 'TEST-006: 継続用プロセス開始。位置情報は保存・送信しません。'
  result=0
  sh start_probe.sh --python-crypto --samples 12 --seconds 45 --output runtime/test-006 || result=$?
  if kill -0 "$keeper" 2>/dev/null; then
    echo 'TEST-006: 終了時も継続用プロセスは生存。これから停止を要求します。'
  else
    echo 'TEST-006: 継続用プロセスは既に終了しています。'
  fi
  exit "$result"
)
```

ゲームが開いたら操作せず、約1分後にiSHへ戻る。戻ったとき終了済みだったか、その瞬間から処理が進んだかも記録する。位置情報の確認が出た場合はその有無と選択を添える。終了しなければCtrl+Cを1回押す。無応答なら画面を記録し、以前のLoopCtrl停止操作（音量ボタン両押し）でサービスを停止し、iSHをアプリスイッチャーから終了する。強制終了では補助プロセスのtrapが実行されたとは保証しない。終了確認まで追加実行や圧縮へ進まない。通常終了でもreaderの停止完了を端末上で確認する計測はないため、終了画面を残したらiSHをアプリスイッチャーから終了して今回の位置情報読取りを終えてから、ファイルを圧縮する。ホストでreader終了を確認できてもiSHでの停止保証とはしない。

終了後、`runtime/test-006`を圧縮したZIPと終了画面を送る。ゲームが開いたか、試験中にiSHへ戻ったか、Ctrl+Cや強制終了を使ったかを添える。`.loopctrl`や位置情報は送らない。保存画像がゲーム以外の場合は秘密値の有無を確認する。フォルダがない場合も繰り返さず画面を残す。
