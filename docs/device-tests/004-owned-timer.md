## 実施時の手順（再実行は不要）

1. `necrogold-p1.4-probe.zip`を「ファイル」で展開。旧フォルダは残し、新しい展開済みフォルダを選ぶ。

```sh
mkdir -p /mnt/necro_p14
mount -t ios . /mnt/necro_p14
cd /mnt/necro_p14
python3 -c 'import necroprobe; print(necroprobe.VERSION)'
```

選択するのは`start_probe.sh`が直下にあるフォルダ。表示が`P1.4`であることを確認。展開済みなのでZIPを解凍するコマンドは不要。

2. LoopCtrlを以前の接続状態で起動。ゲームは通常オールゾーン1-1のポーズ画面、端末は左側が下。既存鍵の再設定は不要。音量ボタン両押しでサービスを停止していた場合はサービスを再開する。

3. 次を1回実行する。Python暗号・12取得・45秒の条件はTEST-003と同じ。

```sh
sh start_probe.sh --python-crypto --samples 12 --seconds 45 --output runtime/test-004
```

ゲームへ切り替わったら操作せず、約1分後にiSHへ戻る。エラーで先に終わったら再実行せず結果を残す。停止はiSHのCtrl+C。以前の`start.sh`や別版を併用しない。

4. 「ファイル」で`runtime/test-004`を圧縮し、そのZIPと「ゲームへ切り替わった／切り替わらなかった」を送る。診断結果に秘密鍵やtokenは含めない設計。`.loopctrl`フォルダは送らない。

## 判定と次の分岐

| 観測 | 判断と次の対応 |
| --- | --- |
| timer_setup_failed / timer_initializeで異常終了 | 所有開始の互換性が未解決。追加でゲーム操作せず、保存reportを分析 |
| timer_already_in_use | Python側の二重所有/ネストを示す。旧値由来とは別の実装不具合として調査 |
| 起動要求の後もゲームが開かない | 起動経路は未解決。応答があっても合格にしない |
| ゲームが開き、原画像にポーズ画面が写る | 起動・画像取得の項目のみ確認。P1全体の合格ではない |
| 取得完了でも黒画像・別画面・古い画像 | 取得の有効性は未合格。金壁なし判定に進まない |
| ポーズのまま | 診断版の仕様。続行タップ・ゲーム操作E2Eは未実行 |

成功した場合、次は入力先・向き・座標変換を確認して、[最小の実ゲームE2E](game-e2e.md)「ポーズ取得→ゲームを続行1回→新しいプレイ画面」を実装・測定する。通常開始でオプションを開かない。取得の問題が残る場合はその修正を優先する。
