# TEST-001: ポーズ画面の取得と遅延

記録作成・結果受領: 2026-11-05（日本時間）。状態: 2実行の終了画面を受領、report.jsonは未受領。結果: 2回ともworker_failed。下記の元手順は試験時点のまま保持。

## 固定した対象

| 項目 | 値 |
| --- | --- |
| ツール版 | P1.1 |
| 対象コードcommit | `1f78c4ba4f213e843b9b76503ccb7988c4be30ae` |
| 配布ZIP | `necrogold-p1-probe.zip`（112ファイル） |
| ZIPのSHA-256 | `0b5002938a64fe8bbca7945746a2bfe8f20671e54a7f14ca63d5cafc5f89413b` |
| 開始場面 | 日本版ネクロダンサー、通常オールゾーン1-1のGAME PAUSE。金壁の有無は問わない |
| 端末の向き | ユーザー指定の「左側が下」 |
| 取得条件 | JPEG quality 0.6 scale 1 / JPEG quality 0.6 scale 2 / PNG scale 1を順番に各4回 |
| 試行・期限 | 12試行、全体45秒、RPC上限8秒 |
| 出力基点 | 展開先の`runtime/test-001/`。その下に実行ごとの`probe-日時-識別子/`を作成 |

目的は、実際のゲームのポーズ画面が取得できるか、返却画像の寸法・黒画像・取得と復号等の時間を比較することです。ゲーム内タップを行わないので、ポーズのまま動かないことは今回の正常動作です。自動周回の開始・速さ・画像の鮮度・座標の正しさの合格試験ではありません。

## 手順

1. 旧版の自動操作が動いていれば停止する。iSHの旧版プロセスが実行中ならCtrl+Cで終了する。旧版フォルダは上書きしない。
2. 指定ZIPをiPhoneの「ファイル」に保存し、ZIPをタップして展開する。`start_probe.sh`と`necroprobe`が入っているフォルダを使う。ZIPをPythonで再展開する必要はない。
3. iSHで以下を実行する。フォルダ選択画面では、手順2の`start_probe.sh`が入っているフォルダを選択する。

```sh
mkdir -p /mnt/necro_p1
mount -t ios . /mnt/necro_p1
```

4. マウントが成功したら、以下でファイルと版を確認する。`start_probe.sh`と`P1.1`が出ること。見つからない場合は実行を続けず、表示を残す。

```sh
cd /mnt/necro_p1
ls start_probe.sh
python3 -c 'import necroprobe; print(necroprobe.VERSION)'
```

5. 前回と同じLoopCtrlの接続を使い、サービスが稼働していることを確認する。音量ボタン両押しで停止していた場合はサービスを再開する。既存のペアリングは作り直さない。これまで必要だったVPN等の接続条件を維持する。
6. ゲームを通常オールゾーン1-1のGAME PAUSEにしてからiSHへ戻る。端末は従来どおり「左側が下」でゲームを見る。操作設定・オプションは変更しない。
7. iSHで次を1回実行する。

```sh
sh start_probe.sh --samples 12 --seconds 45 --output runtime/test-001
```

8. ゲームが自動で開いたら、画面を触らず約1分待ってiSHへ戻る。ゲームを続行しない。計測中はアプリ切替・画面ロック・別の録画開始を挟まない。ゲームが開かない、エラーが出る場合はその状態を記録し、設定変更や再試行をせず結果を渡す。
9. iSHに表示される「診断終了」「保存先」を含む画面を残す。iSHへ戻って初めて処理が進んだように見えた場合は、その旨も記録する。バックグラウンドで継続実行できるか自体が未検証のため、成功を仮定しない。
10. 「ファイル」で展開先 → `runtime` → `test-001`を開く。今回できた`probe-…`フォルダを長押しして圧縮し、ZIPをチャットに添付する。この1実行分だけを送る。

Pillowが必要という表示だけが出た場合は、iSHで`apk add py3-pillow`を実行し、成功後に手順7を実行する。依存関係の追加を準備記録に残す。その他のエラーで同じ処理を繰り返さない。

## 期待する表示と例外

- 開始時: 「画像取得の診断を開始します。タップ・オプション操作は行いません。」
- 終了時: 「診断終了: … / 取得完了 …/12 / エラー … / 未実施 …」と保存先。
- `report.json`と加工前の画像（各条件で黒・非黒を最大1枚ずつ、合計最大6枚）が診断資料。12試行すべての画像を保存する仕様ではない。
- `blank_or_dark`でも資料として有用。取得完了12/12でも黒画像だけなら「ゲーム画面を取得できた」とは判定しない。
- 画面上のゲームと保存画像が一致するかはユーザー観察と保存画像の両方で確認する。静止ポーズ画面だけでは鮮度を証明できない。
- 45秒は設定した処理期限。iSHの休止や終了処理を含む実際の経過時間は別に記録する。
- 中断する場合はiSHへ戻ってCtrl+C。LoopCtrl側の緊急停止を使った場合は、その操作とタイミングを報告する。中断も失敗も元の結果として保存する。
- `gate.P1: not_passed`は今回の仕様。P1全体の合格ではないことを表し、それだけでツールの障害とは扱わない。

## 渡してもらうもの

1. 今回の`probe-…`フォルダを圧縮したZIP。画像とreport.jsonを含む。
2. iSHの終了画面のスクリーンショット。出力フォルダができなかった場合はエラー画面だけでもよい。
3. 短い観察: 「ゲームが自動で開いたか」「GAME PAUSEのままだったか」「約1分後のiSH復帰で初めて動き出した様子があったか」。

ペアリング用の`.loopctrl`やtoken.jsonを含めない。ゲーム以外が写った画像があれば、共有前に知らせてもらう。診断ツール自身は結果を外部送信しない。
