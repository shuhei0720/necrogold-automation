# TEST-007: 同じゲーム取得条件で既存のネイティブ復号を比較

状態: **手順準備・実機未実行**。2026-11-05（日本時間）。P1.4の既存機能を使用し、コードの入れ替え・ライブラリの追加はしない。

## 1. 概要

TEST-006では継続処理付きで12/12非黒取得、保存3枚でゲームのポーズ画面を確認し、32.9秒で正常終了した。Python復号だけでJPEG scale1の中央値375.666ms、scale2で998.792ms。次は既存のネイティブ復号を優先する起動に切り替え、実際に使用されたエンジンと時間を確認する。

## 2. 背景と根拠

`necroprobe/crypto.py`の既存実装は、同梱i386ライブラリのサイズとSHA-256、OpenSSL関数、既知入力のPython版との一致を確認してから`native_i386`を選ぶ。初期化時の条件不成立や捕捉対象の例外では`python`を使う。実データのネイティブ復号失敗やSIGSYS等まで自動でPythonへ切り替わるわけではなく、異常終了は別に記録する。`--python-crypto`の省略はネイティブ使用の保証ではない。過去のSIGSYSだけで現在のネイティブ方式の可否は判断できない。

TEST-006の[原資料からの派生結果](test-006-results.json)を基準にする。画像取得・復号は確認できたが、鮮度、座標、取消、長時間動作、人より速い周回は未確認。P1全体は未合格。

## 3. 比較設計

P1.4、同じゲームのポーズ、端末の左側が下、継続用読取り、12試行、45秒、JPEG/PNGの既存3条件を維持する。TEST-006のコマンドから`--python-crypto`だけを省き、出力先と表示ラベルをTEST-007へ変える。ゲーム内タップはしない。

reportの`crypto_engine`を先に確認し、`native_i386`の場合だけネイティブの測定値として扱う。各形式の完了件数・失敗/中断/未実施と復号、HTTP、画像検査までの中央値/p95を比較する。画像バイト数・オーバーレイの有無・端末負荷で値は変わるため、1回の比較を厳密な速度保証としない。同じ形式で同じSHA-256の画像がある場合は、その試行の時間も別に比較する。ウォームアップや不都合な失敗を黙って除外しない。

## 4. 影響範囲

既存プログラム、旧R12、ペアリング、OS設定は変更しない。既存の同梱ライブラリだけを使い、新規ダウンロードはしない。位置情報は試験中に`/dev/null`へ読み捨て、保存・送信しない。readerの生存確認は許可や位置情報配信の確認ではない。終了時は所有PIDに停止要求を出すが、実機の停止完了を保証しないため、終了画面を記録してからiSHをアプリスイッチャーから終了する。

## 5. 判定条件

| 観測 | 判定・次の対応 |
| --- | --- |
| native_i386、ゲーム画像保存、完了 | 既存ネイティブ復号の実機利用を確認。件数と時間をPython結果と比較。座標・鮮度・P1全体の合格とは別 |
| pythonで完了 | フォールバックで取得できた結果。ネイティブの速度として扱わない。ライブラリ/依存関係の読取り診断を次に計画 |
| worker_failed / SIGSYS / 0枚 | 段階・終了理由を記録。ネイティブが原因と即断せず、再実行やインストールをせず資料を残す |
| 一部取得、期限切れ、黒画像、別アプリ画像 | 条件ごとの成功と未成立を分離。速度結果を完了分だけで成功扱いしない |
| locationが読めない、reader開始失敗、許可しない | 比較条件未成立。位置情報を許可しない場合はCtrl+Cで終了 |
| 終了時readerが既に終了 | 継続条件は不明。正常継続した比較として扱わない |

## 6. 実行手順

前回のiSHをアプリスイッチャーから終了していない場合は、終了してから開く。LoopCtrlを以前の接続状態にし、ゲームを前回と同じポーズ画面にしてiSHへ戻る。既存のP1.4で次のブロック全体を1回だけ実行する。

```sh
cd /mnt/necro_p14 && (
  set -eu
  if [ ! -r /dev/location ]; then
    echo 'TEST-007: /dev/locationを読めません。試験は開始していません。'
    exit 1
  fi
  cat /dev/location >/dev/null 2>/dev/null &
  keeper=$!
  trap 'kill "$keeper" 2>/dev/null || true' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  sleep 1
  if ! kill -0 "$keeper" 2>/dev/null; then
    echo 'TEST-007: 継続用プロセスを開始できませんでした。'
    exit 1
  fi
  echo 'TEST-007: 継続用プロセス開始。位置情報は保存・送信しません。'
  result=0
  sh start_probe.sh --samples 12 --seconds 45 --output runtime/test-007 || result=$?
  if kill -0 "$keeper" 2>/dev/null; then
    echo 'TEST-007: 終了時も継続用プロセスは生存。これから停止を要求します。'
  else
    echo 'TEST-007: 継続用プロセスは既に終了しています。'
  fi
  exit "$result"
)
```

ゲームが開いたら操作せず約1分待ち、iSHへ戻る。戻った時点で終了済みだったか、戻ってから処理が進んだかを添える。位置情報の確認が出た場合の有無と選択も添える。許可しない場合はCtrl+Cで終了する。

終了しなければCtrl+Cを1回押す。無応答なら画面を記録し、以前のLoopCtrl停止操作（音量ボタン両押し）でサービスを止め、iSHをアプリスイッチャーから終了する。通常終了でも、画面を記録したらiSHをアプリスイッチャーから終了し、位置情報読取りを終えてから圧縮する。停止完了を確認できない場合は追加実行せず、その状態を報告する。

`runtime/test-007`を圧縮したZIPと終了画面を送る。原画像はゲーム以外や秘密値が写っていないか確認し、`.loopctrl`は含めない。ゲームを続行したりオプションを開いたりする必要はない。
